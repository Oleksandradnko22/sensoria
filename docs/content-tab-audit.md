# Аудит кабинета автора: «Контент» и «Огляд»

2026-11-11. Проверено: список контента, создание и редактирование медитаций, гайдов и программ, архив, восстановление, удаление черновиков, правила продажи и доступа в базе, оплата, действия админки над материалами, вкладка «Огляд».

## Исправлено в этом аудите

### Критичное
1. **Архив игнорировал запросы на возврат.**
   - Было: запрос на возврат (`refund_requests`) не был связан с покупкой, поле `purchase_id` всегда оставалось пустым. Поэтому база не знала об открытых запросах, и материал можно было архивировать, пока возврат ещё рассматривается.
   - Стало: запрос привязывается к своей покупке. Подать его можно только на собственную оплаченную покупку не старше 14 дней.
   - Архивация запрещена, пока есть открытый запрос (`supabase/archive-refund-guard.sql`). В кабинете кнопка «Архівувати» приглушена и объясняет причину.
2. **Снятие с публикации через API обходило правило 14 дней.**
   - Было: база проверяла только переход в «архив». Переход published → draft снимал материал с продажи без проверки.
   - Стало: та же проверка для обоих переходов.
3. **Демо-данные «Андрія» у каждого реального автора.**
   - Было: его материалы, участники, доход и события подмешивались в «Контент» и в итоговые цифры «Огляд». Реальный автор видел чужой доход как свой.
   - Стало: демо в кабинете автора включается только флагом `VITE_SHOW_AUTHOR_DEMO=true`.
4. **У реальных материалов всегда было 0 участников, «—» в доходе и рейтинге.**
   - Стало: цифры берутся из покупок, прогресса и отзывов (`fetchContentMetrics`).
   - Архивные и снятые с публикации материалы тоже показывают своих участников: доступ у людей остаётся.
5. **Админка могла удалить бесплатный материал**, который люди уже добавили в кабинет или начали проходить. Они теряли доступ. Теперь удаление в этом случае запрещено (`admin-data`).
6. **Файлы уроков платных программ лежали в открытом хранилище** (исправлено ранее сегодня). Теперь они защищены, а при смене цены переносятся автоматически.

### Нагрузка
- «Огляд» для подсчёта участников загружал профили всех людей и все уроки всех программ, по запросу на каждую программу. Убрано: итог считается из уже загруженных цифр списка.

### Дизайн
- В «Огляд» убран эмодзи 👋 из приветствия, по правилу «без эмодзи на платформе».

## Что нужно сделать вам
1. Выполнить в Supabase SQL Editor: `supabase/archive-refund-guard.sql`.
2. Задеплоить функцию: `supabase functions deploy admin-data`.
3. Демо-материалы «Андрія» по умолчанию скрыты. Если они нужны для показа, добавьте `VITE_SHOW_AUTHOR_DEMO=true`.

## Не исправлено: рекомендации

### Логика
1. **«Дохід» в «Контент» и «Огляд»** — это сумма продаж до комиссии Sensoria, а «Фінанси» показывают долю автора. Рекомендация: переименовать колонку в «Продажі» или показывать долю автора.
2. **«Учасники» в «Огляд»** — сумма по материалам: человек, купивший два материала, считается дважды. Для точного числа уникальных людей нужен отдельный лёгкий запрос в базе.
3. **Гонка при оплате.** Если автор архивирует материал между выставлением счёта и подтверждением оплаты, покупка всё равно пройдёт (`finance`, webhook). Это редкий случай, деньги и доступ корректны. Но архив тогда окажется «моложе» 14 дней после покупки. Можно отклонять такую оплату с автоматическим возвратом.
4. **Старые запросы на возврат без `purchase_id`** не блокируют архив. Команде стоит привязать открытые запросы вручную или закрыть их.
5. **Статус «На модерації»** есть в фильтрах. Премодерация осталась только для первого материала автора. Стоит проверить, понятен ли этот статус авторам.

### Дизайн и единообразие
1. **Два градиента бренда:** `#3b6df0 → #7c5cf0` (список, «Огляд») и `#5232f4 → #774eff` (редактор, студия). Нужно выбрать один.
2. **Похожие подписи:** «Знято з публікації» (восстановлено из архива) и «Знято з продажу» (решение админки) легко спутать. Предлагаю «Повернуто з архіву» для первого.
3. **По 4 материала на страницу** в «Контент» — мало для активного автора. Предлагаю 8–10.
4. **Дублирование кода:**
   - `ConfirmDialog` и меню «Створити» продублированы в `AuthorContentList` и `AuthorOverview`. Есть общий `ConfirmDialog.tsx`, стоит использовать его.
   - Кнопки и чипы списка (`rounded-2xl`, `#12172b`) отличаются от редактора (`rounded-xl`, `#1d1a3b`).
5. **Таблица списка** включается только с 1400 px. На ноутбуках 1280–1440 px показываются карточки. Можно включать с 1200 px, сузив колонки.
6. **«Огляд»:** события грузятся заново только при изменении числа материалов (`content.length`). Переименование или смена статуса не обновляют ленту до перезагрузки.

### Тесты
- Нет тестов на правило «открытый возврат блокирует архив» (оно в SQL). Стоит добавить ручной QA-сценарий в `docs/meditation-manual-qa.md` и `docs/program-manual-qa.md`.
