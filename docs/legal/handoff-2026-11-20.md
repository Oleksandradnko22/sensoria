# Розробнику: юридичні правки, погоджені 20.11.2026

Усе нижче погоджено юристом і власницею. Тексти переносити **дослівно** з указаних файлів і розділів (у файлах — блоки `>`, службові примітки `> Службове` не переносити). Решта раніше переданих правок уже на сайті — перевірено 20.11.2026.

## 1. Оферта для авторів — `src/pages/AuthorAgreementPage.tsx`

Джерело: `docs/legal/author-consent.md`.

| Правка | Розділ оферти | Що |
|---|---|---|
| **Б39а** | `chargebacks`, у кінці після Б39 | Плату банку за опрацювання спірного платежу несе Автор |
| **Б43** | `taxes`, після абзацу про ПРРО Автора | Каса обов’язкова; перевірка при підключенні й щодня; призупинення продажу |
| **Б44** | `taxes`, після Б43 | Підтримується лише Checkbox; вартість каси — Автор; можлива партнерська винагорода Оператора |
| **Б45** | `participant-data`, у кінці першого абзацу | Автор отримує маскований номер картки, платіжну систему, код авторизації й RRN у чеках |

## 2. Політика конфіденційності — `src/pages/PrivacyPage.tsx`

Джерело: `docs/legal/privacy-edits.md`, розділ **П16** (повністю, разом із доповненням від 20.11.2026):

1. `what` — абзац про дані картки: замість «лише статус оплати й тип картки» — повний перелік (маскований номер, платіжна система, код авторизації, номер транзакції).
2. `access` — рядок «Касовий сервіс (ПРРО) продавця…» — новий текст.
3. `access` — **новий рядок** «Касовий сервіс (ПРРО) Sensoria — для документа на суму тарифу…» одразу після рядка про касу продавця.
4. `access` — у рядку «Автор матеріалу, який ви придбали…» замінити речення «Вашу електронну адресу автор не бачить.» на нове (два речення).

## 3. Угода учасника — `src/pages/ParticipantAgreementPage.tsx`

Джерело: `docs/legal/participant-agreement.md` — синхронізувати сторінку з файлом побуквено. Змінився лише **п. 9.3** (додано друге речення про дані оплати, які бачить автор як продавець). Хеш редакції для екрана згоди — оновити, як при попередніх правках.

## 4. Перевірка після внесення

- Тест на побуквений збіг текстів з `docs/legal` проходить.
- Пошук по `src/pages`: «лише статус оплати й тип картки» — 0 збігів; «партнером сервісу Checkbox» — 1; «не є тестовою та працює» — 1; «плату за опрацювання спірного платежу» — 1; «Касовий сервіс (ПРРО) Sensoria» — 1.
- `npm run build` і тести проходять.

## Коли зміняться обставини (не зараз)

- **Відповідь ДПС на ІПК** щодо чека на тариф: якщо чек Sensoria не потрібен або з нього приберуть реквізити картки — прибрати рядок «Касовий сервіс (ПРРО) Sensoria…» з Політики та згадку «документа Sensoria на тариф» у Політиці, п. 9.3 Угоди й Б45 оферти (юрист надасть нові тексти).
- **Інші сервіси ПРРО**: якщо додасте не лише Checkbox — тексти Б44 уже це покривають, змінювати не треба.
- **Заява про інформаційне партнерство з monobank**: не підписувати до перегляду юристом.
