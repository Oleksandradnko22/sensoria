# Відкладений деплой: фінансовий блок (на паузі)

Статус: код готовий, нічого не виконано в Supabase. Фінанси на паузі до відповіді monobank.
Вмикати лише в такому порядку. Режим усюди `test`, реальні гроші не рухаються.

## 1. SQL (Supabase → SQL Editor)
Після `account-deletion-migration.sql` та `no-premoderation-migration.sql` (вони вже виконані):

1. `supabase/finance-migration.sql` — повторно запускається безпечно. Створює журнал, баланси, платежі,
   рахунки авторів, налаштування (комісія каталог 30%, реферальна 15%, розподіл при оплаті),
   `content_access_log`, `referral_attributions`, функцію `claim_referral`.

`supabase/schema.sql` містить той самий блок, його окремо запускати не потрібно.

## 2. Edge Functions (Dashboard, вставка одного файлу)
- `finance` ← `supabase/functions/finance/index.ts` (генерується: `npm run build:finance`)
- `log-content-access` ← `supabase/functions/log-content-access/index.ts` (потребує таблиці з кроку 1)

Секрети: `CRON_SECRET`, `RESEND_API_KEY`, `RESEND_FROM`. Cron: щодня виклик дії `runJobs` із заголовком `x-cron-secret`.

## 3. Що перевірити після деплою
- Адмінка → «Фінанси»: відкривається, налаштування читаються (30% / 15%).
- Кабінет автора → «Фінанси»: баланс 0, форма банківського рахунку.
- Кабінет автора → «Просування»: реферальне посилання відкривається, а після входу покупця з'являється запис у `referral_attributions`.

## 4. Блокує запуск реальних платежів (не код)
- Відповідь monobank (розщеплення / агентська схема, підключення авторів, тарифи).
- Юридичне: див. `docs/legal-todo.md` (розкриття комісії покупцю, борг після повернення, політика конфіденційності, консультація ДПС про базу оподаткування).
- Режим `live` у коді заблокований, поки не підключено банківський шар.

## 5. Не реалізовано
- Форма оплати для покупця (чекаут) і адаптер до API monobank.
- Статистика кліків і покупок за реферальним посиланням у кабінеті автора.
